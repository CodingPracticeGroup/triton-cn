---
title: 浮点检查器 (Floating-Point Sanitizer, FpSan)
---

FpSan 是一种编译器插桩 (instrumentation) 模式，它把选定的浮点 Triton IR 操作重写为在整数位模式 (bit-pattern) 上进行的确定性的“载荷代数 (payload algebra)”。它的目标不是逼近 IEEE 浮点算术。相反，它保留选定的代数结构，使得在插桩后的语义下符号等价的内核仍然给出一致的结果；而错误的重写、错误的操作数、错误的数据流或缺失的同步，往往会使结果发生扰动。

因此 FpSan 主要是一种内核检查工具。当你更关心某个内核是否保留了预期的符号计算，而不是它在某个特定输入上的确切 IEEE 结果时，FpSan 尤其有用。

从高层次上看，FpSan 会：

- 把浮点位模式映射到一个整数载荷域
- 用整数域上的重写替换所支持的浮点算子，这些重写的选取目标是精确保留某些恒等式
- 再把得到的载荷映射回浮点位模式，以便流水线的其余部分继续执行

## 启用 FpSan

在你希望插桩的那次编译或运行之前启用 FpSan。

在 Python 中：

```python
import triton

triton.knobs.compilation.instrumentation_mode = "fpsan"
# compile and run kernels here
# 在此处编译并运行内核
triton.knobs.compilation.instrumentation_mode = ""
```

在 shell 中：

```bash
TRITON_INSTRUMENTATION_MODE=fpsan python your_script.py
```

注意：

- FpSan 是编译器特性，因此不适用于解释器 (interpreter) 模式。
- 在 AMD 上，后端目前仅针对 `gfx942`、`gfx950` 和 `gfx1250` 启用 FpSan。

## 如何使用

使用 FpSan 最有效的方式，是在同一个 FpSan 模式下比较两个内核，或者比较同一个内核的两个版本。典型用途包括：

- 将一个优化后的内核与一个简单的参考内核进行比较
- 将一个融合内核与一个未融合的组合作进行比较
- 比较两个应当在数学上等价的调度变体
- 检查累加器选择、谓词化 (predication) 或张量内存 (tensor memory, TMEM) 流水线是否保留了预期的载荷流动

FpSan 的结果只应与其他 FpSan 的结果相比较，而不应与普通的浮点输出相比较。

## 载荷模型

对每一种浮点位宽 `w`，FpSan 都在浮点位模式与一个 w 位整数载荷之间定义了一个双射 (bijection)；算术按 2^w 回绕取模。

概念上：

- `embed(x)` 把浮点位模式映射为整数载荷
- `unembed(u)` 把整数载荷映射回浮点位模式
- 插桩后的浮点算子实现为 `unembed(F(embed(...)))`

嵌入映射 (embedding) 是经过刻意选取的，使得若干重要常量保持稳定：

- `embed(+0.0) = 0`
- `embed(+1.0) = 1`
- `embed(-1.0) = all-ones`

这些不动点正是 `x + 0 = x`、`x * 1 = x` 这类恒等式在 FpSan 下表现自然的原因。

## FpSan 保留什么

FpSan 在每次重写所选取的载荷代数中保留精确的恒等式。其中最重要的是：

- 加法、减法、一元取负、乘法、FMA 以及类 dot 累加的环恒等式
- `exp` 与 `exp2` 的部分指数恒等式（细节见下文）
- `sin` 与 `cos` 的三角恒等式
- 经过类型转换、load、store 与 copy 之后载荷保持相等
- 对尚无更丰富代数模型的一元函数，给出确定性的、可区分算子的标签

这正是 FpSan 对内核检查有价值的原因：如果两个内核在被保留的这些性质下应当是同一个符号计算，它们就应当产生相同的载荷。这一结论以一个（普遍被认为成立的）超越数论中的猜想——沙努尔猜想 (Schanuel's conjecture)——作为前提。FpSan 的一位作者写过[一篇博客文章](https://cp4space.hatsya.com/2026-05-03/schanuels-conjecture-and-the-semantics-of-fpsan/)，从数学角度解释 FpSan 背后的理论。

## FpSan 不保留什么

FpSan 不是 IEEE 模拟器。

尤其不要指望它处理以下内容：

- 真实的浮点大小顺序、舍入、NaN 传播、无穷值、次正规数 (subnormals) 或异常
- `log`、`sqrt`、`erf`、`floor`、`ceil`、`rsqrt` 以及同类带标签一元算子的真实超越函数语义
- 预期的浮点位模式（也就是那些在浮点数与整数之间做 bitcast 的内核）

当某个性质对你的检查很重要时，正确的问题是：“对于这个特定的算子族，该性质是否被它的载荷重写所保留？”

## 常见算术算子

### 加、减、取负、乘

支持的算子：

- `x + y`
- `x - y`
- `-x`
- `x * y`

重写方式：

- 对嵌入后的载荷执行加、减、取负或乘，然后再 unembed 结果

精确保留的性质：

- `x + 0 = x`
- `x - 0 = x`
- `x - x = 0`
- `x + (-x) = 0`
- `-(-x) = x`
- `x * 1 = x`
- 加法与乘法的结合律和交换律
- 乘法对加法的分配律

重要注意事项：

- 这是模 `2^w` 的环算术，不是 IEEE 算术。

### 绝对值

支持的算子：

- `tl.abs(x)`

重写方式：

- 清除 `x` 的符号位，保留其他所有位，包括 NaN 的位

它的实现方式是对 `embed(x)` 求有符号整数的绝对值，在 unembed 之前把最负的载荷映射为零。

精确保留的性质：

- `abs(x) = abs(-x)`
- `abs(abs(x)) = abs(x)`
- 在有符号载荷顺序下 `embed(abs(x)) >= 0`

重要注意事项：

- 除负零之外 `abs(x) = maximum(x, -x)`。负零的载荷是最小的有符号整数，它在 FPSan 的取负运算下会回绕到自身。因此 `maximum(x, -x)` 返回负零，而 `abs(x)` 返回正零。

### Min、Max 与 Clamp

支持的算子：

- `tl.minimum(x, y)`
- `tl.maximum(x, y)`
- Triton 代码中的 `min(x, y)` 与 `max(x, y)`
- `tl.clamp(x, lo, hi)`

重写方式：

- 在载荷上执行有符号整数的 `min` 或 `max`
- clamp 变为同一有符号载荷顺序下的 `min(max(x, lo), hi)`

精确保留的性质：

- 幂等律：`min(x, x) = x` 与 `max(x, x) = x`
- 交换律
- 结合律
- `clamp(x, lo, hi) = min(max(x, lo), hi)`

重要注意事项：

- 这里的顺序是载荷的有符号整数顺序，不是 IEEE 浮点顺序。
- 没有对 NaN 的处理方式以及确切的带符号零约定进行建模。
- `propagate_nan` 的两种模式使用相同的载荷语义。

### 除法

支持的算子：

- `x / y`

重写方式：

- `x / y` 变为 `embed(x) * inv(embed(y))`，然后再 `unembed`

这里 `inv` 的定义是：

- 对奇数载荷，取真正的模逆
- 对偶数载荷，取一个保持奇偶性的对合 (involution)

精确保留的性质：

- `x / 1 = x`
- `1 / (1 / x) = x`
- 对奇数载荷，通常的模逆定律成立

重要注意事项：

- `x / x = 1` 并不能保证对所有载荷成立。
- 除以零不会产生 IEEE 无穷值，也不会触发 trap。
- 选择这一重写是为了代数检查，而不是为了数值的真实性。

### 取余

支持的算子：

- `x % y`

重写方式：

- 先用 `den | 1` 把分母强制为奇数，然后在载荷上执行有符号整数取余

精确保留的性质：

- 相同的输入会产生相同的插桩后余数载荷

重要注意事项：

- 没有对真实的浮点取余语义进行建模。
- 分母为零会被刻意映射到一个安全的奇数载荷，而不是触发 trap。

### FMA

支持的算子：

- `tl.fma(a, b, c)`

重写方式：

- 在载荷算术中计算 `a * b + c`

精确保留的性质：

- 与插桩后的展开——先 `mul` 再 `add`——精确一致
- 在载荷环中 `fma(a, b, c) = a*b + c`

重要注意事项：

- 不存在任何特殊的融合舍入行为。

### 可选的表达式边界

使用 `tl.fpsan.barrier(x)`（在 Gluon 中为 `gl.fpsan.barrier(x)`）可以让某个中间结果在 FpSan 的比较中变得有意义。输入必须是浮点标量或张量；它的类型、形状和布局都会被保留。

在启用 FpSan 的情况下，barrier 会对每个元素的载荷施加一个确定性的、非同态的变换。例如：

```python
left = tl.fpsan.barrier(a * b) * c
right = a * tl.fpsan.barrier(b * c)

unfused = tl.fpsan.barrier(a * b) + c
fused = tl.fma(a, b, c)
```

这些成对的写法可能得到不同的 FpSan 结果。若没有这些 barrier，每一对都具有相同的载荷代数。请把 barrier 放在边界真正重要的那个中间结果上：只包裹最终结果，无法区分那些载荷已经相同的表达式。

每一个 barrier 使用的都是同一个变换，与它在源码中的位置无关。因此，带有相同标注的等价计算在各个内核之间仍然会给出一致结果。每次调用都会再次应用该变换；嵌套的 barrier 并不是多余的。与其他 FpSan 检查一样，不同的计算在特定输入下可能发生碰撞，所以结果相同并不能证明两者等价。

在禁用 FpSan 时，这个函数原样返回它的输入，并且不发出任何操作。它不会强制舍入，不会在普通编译中阻止融合或重结合，也不会同步执行。

### 局部同态类型转换

`tl.fpsan.homomorphic_cast(x, dtype)`（在 Gluon 中同样可用）在转换到更窄的浮点类型时，会显式保留低位的载荷位。它使加法和乘法在这次转换前后保持不变。其他类型转换保持其已有的 FpSan 语义。

使用 barrier 可以标出这类转换最多能被移动多远而不改变 FpSan 签名：

```python
result = tl.fpsan.homomorphic_cast(tl.fpsan.barrier(a * b), tl.float16)
```

barrier 会在高位载荷位被丢弃之前，把它们混合进低位。因此，把这次向下转换移到 barrier 之前，通常会改变结果；即使是在 barrier 之前把已窄化的值重新转回原始位宽，情况也是如此。这只是签名上的区分，并不是对编译器优化的限制；碰撞仍然可能发生。

源类型与目标类型都必须是浮点类型，并且目标类型的位宽必须与源相同或更窄。同位宽的转换会保留载荷。加宽 (widening) 会被拒绝，因为符号扩展不是环同态。在未启用 FpSan 的情况下，这个函数执行的是一次普通的浮点类型转换，可选参数 `fp_downcast_rounding` 的解释方式与 `tl.cast` 相同。

## 一元数学算子

### `exp2`

支持的算子：

- `tl.exp2(x)`

重写方式：

- 在载荷空间中，以一个固定的奇数生成元为底进行模指数运算

精确保留的性质：

- `exp2(x + y) = exp2(x) * exp2(y)`
- `exp2(0) = 1`
- `exp2(-x) = 1.0 / exp2(x)`

### `exp`

支持的算子：

- `tl.exp(x)`

重写方式：

- `exp(x)` 在载荷空间中实现为 `exp2(x * rcp_log2)`

精确保留的性质：

- `exp` 在把输入乘以一个固定的内部载荷常量之后，采用与 `exp2` 相同的载荷空间构造方式

### `sin` 与 `cos`

支持的算子：

- `tl.sin(x)`
- `tl.cos(x)`

重写方式：

- 一个确定性的载荷空间重写，其选取目标是为了保留下面这些恒等式

精确保留的性质：

- `sin(x + y) = sin(x) * cos(y) + cos(x) * sin(y)`
- `sin(x - y) = sin(x) * cos(y) - cos(x) * sin(y)`
- `cos(x + y) = cos(x) * cos(y) - sin(x) * sin(y)`
- `cos(x - y) = cos(x) * cos(y) + sin(x) * sin(y)`
- `cos(x)^2 + sin(x)^2 = 1`

重要注意事项：

- 这些不是 IEEE 的三角函数值；它们是为了保留上述角度恒等式而选取的载荷函数。

### 带标签的一元算子

支持的算子：

- `tl.log(x)`
- `tl.log2(x)`
- `tl.sqrt(x)`
- `tl.rsqrt(x)`
- `tl.erf(x)`
- `tl.floor(x)`
- `tl.ceil(x)`
- 精确平方根的各种变体

重写方式：

- 一个可逆的载荷标签：先乘以一个奇数常量，再与该算子专属的散列值异或 (xor)，然后再乘一次

精确保留的性质：

- 对同一个算子保留载荷相等：若在载荷空间中 `x == y`，那么 `op(x) == op(y)`
- 不同的受支持一元算子会得到不同的标签

重要注意事项：

- 这些重写刻意不保留真实的数学恒等式，例如 `sqrt(x)^2 = x` 或 `log(x*y) = log(x) + log(y)`。

## 类型转换与格式转换

### 浮点到浮点转换

支持的算子：

- 使用 `x.to(dtype)` 在浮点类型之间转换张量
- 隐式的浮点加宽与窄化转换

重写方式：

- 加宽时执行有符号整数符号扩展
- 窄化时，把被丢弃的高位载荷位折叠进保留下来的位，然后截断并 `unembed`
- 可选地，设置 `TRITON_FPSAN_HOMOMORPHIC_CASTS=1`，以便在窄化时使用简单的载荷截断；这会保留在各自独立向下转换的部分归约之间的加法

精确保留的性质：

- `0`、`+1` 与 `-1` 在转换过程中保持稳定
- 载荷域中的符号扩展行为
- 先加宽再窄化等于恒等变换

重要注意事项：

- 这保留的是载荷结构，而不是 IEEE 的转换语义。
- 位宽相同的浮点类型之间的转换不会建模任何精度或表示范围的损失，因此在 FpSan 下，例如对任意 bfloat16 的 `a`，有 `fn(a.to(tl.float16)).to(tl.bfloat16) == fn(a)`。

### 打包 fp4 转换

重写方式：

- 从源字节张量中解包出低位半字节 (nibble) 与高位半字节
- 对它们进行 reshape 并重排
- 把解包出来的每个半字节直接解释为目标浮点宽度下的一个载荷

精确保留的性质：

- 对打包 fp4 存储的确定性解包
- 精确保留解包后半字节的载荷

重要注意事项：

- 这不是真正的 fp4 数值解码。
- 缩放点积 (scaled-dot) 路径在处理 `e2m1` 时会复用同样的原始载荷解释。

## 纯 extern 与 inline-asm 逐元素算子

支持的算子：

- 当以下条件全部满足时，支持 `tl.extern_elementwise` 与 `tl.inline_asm_elementwise`：
  - 该算子是 `pure` 的
  - 每一个结果类型都是浮点类型（float-like）
  - 至少有一个操作数
  - 每个操作数都是数值类型

重写方式：

- 将每个操作数的载荷按其参数索引进行循环移位 (rotate)
- 对循环移位后的载荷求和
- 将结果与该符号名或 inline-asm 字符串的稳定散列值异或；对于多结果算子，还会把 inline-asm 的结果索引一并纳入
- `unembed`

精确保留的性质：

- 对所有操作数以及操作数顺序的确定性依赖
- 对不同外部符号、不同 inline-asm 字符串以及不同 inline-asm 结果索引的确定性区分
- 支持浮点与整数混合的操作数；浮点操作数会先被嵌入，整数操作数在以有符号方式转换到结果位宽后直接使用

重要注意事项：

- 这是一个结构性标签，并不是对外部函数或内联汇编的数值模型。

## Gluon MMA 与张量内存

支持的 Gluon 算子包括：

- `mma_v2`
- `warpgroup_mma` 与 `warpgroup_mma_wait`
- `tcgen05_mma` 与 `tcgen05_mma_scaled`
- `tcgen05_copy` 与 `tcgen05_commit`
- `allocate_tensor_memory`
- 张量内存描述符 (tensor memory descriptor) 的方法，例如 `load`、`load_min`、`load_max`、`store`、`slice`、`index` 与 `reinterpret`
- AMD 的 `mfma`、`mfma_scaled`、`wmma`、`wmma_scaled` 与 `scaled_upcast`

重写方式：

- 在载荷空间中执行乘加累加
- 在张量内存的 load、store、copy 与 view 之间保留载荷位
- 使累加器选择与谓词化的行为在结构上可见

精确保留的性质：

- 在载荷环上的精确矩阵乘代数
- 与插桩后的标量乘加展开精确一致
- 使用给定累加器进行的累加以载荷加法的形式保留
- 张量内存操作在流水线中保留载荷流动

重要注意事项：

- 缩放 MMA 保留的是检查器对低精度操作数与缩放因子的载荷处理方式，而不是硬件格式的精确数值解码。
- 张量内存操作保留的是载荷数据流；它们并不会让 FpSan 成为竞争条件或同步检查的替代手段。
- 目前 FpSan 支持所有 NVIDIA 硬件，以及 AMD 的 `gfx942`、`gfx950` 和 `gfx1250`。

## 实践建议

在希望检查以下内容时，FpSan 是合适的选择：

- 两个内核是否实现了同一套被保留的代数
- 融合内核是否保持了预期的数据流
- 谓词化或累加器选择逻辑是否连接正确
- 张量内存或 warp 特化的流水线是否保持了载荷流动

在希望检查以下内容时，FpSan 并不合适：

- IEEE 的边界情况
- 真实的超越函数精度
- NaN 或无穷值的行为
- 低精度格式的硬件格式解码语义

简而言之：需要保留结构的内核验证就依赖 FpSan，IEEE 行为则依赖普通的数值测试。
